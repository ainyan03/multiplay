# MULTIPLAY

ブラウザだけで自由に参加・退出できる、サーバーレスP2Pオンライン・ミニゲーム集のプロトタイプです。

## 収録ゲーム

- **GEM SPRINT** — フィールド上の宝石を集めるスコアアタック
- **CROWN CHASE** — 王冠を奪い合い、保持時間を競うおにごっこ
- **BLAST GRID** — 爆風でブロックを壊し、敵と味方を巻き込む常設アリーナ
- **LOBBY PLAZA** — キャラクターで歩き、マップ上の入口からゲームを選べる常設広場

いずれもゲーム中の途中参加・途中退出が可能です。プレイヤーの位置とゲームイベントは約15Hzで同期します。ロビーと全ゲームを横断する常設チャットがあり、発言はログとキャラクター頭上の吹き出しに表示されます。

ロビーのキャラクター同士は円形の当たり判定を持ちます。重なりを互いに押し戻し、接近速度に応じた反発を加えるため、歩いて押したりビリヤードのように弾いたりできます。各端末は自分が相手へ進んでいる速度成分だけを運動量として渡し、相手側へ専用P2Pイベントで直接伝えます。方向転換時は旧方向の慣性成分を先に取り除き、受信した反発も現在の位置関係で相手から離れる向きの場合だけ適用します。

スマホでは全ゲーム共通のアナログスティック、決定／アクションボタン、チャットボタンを表示します。スティック操作中はブラウザの文字選択や長押しメニューを抑止します。ぼかしを使わない薄い半透過コントローラは、通常表示のチャット枠より上に配置して拡大・最小化ボタンを塞がないようにします。チャット入力中は端末の向きにかかわらずコントローラをほぼ透明にして操作を無効化し、スクリーンキーボードが開くと完全に隠します。チャットは最小化・通常・拡大の3段階で切り替えられ、自分と他プレイヤーの発言は色分けされます。

チャットは左右中央に揃えた全幅の下辺ドック式です。入力バーは常に最下端へ表示され、待機時は操作案内、入力時はメッセージ欄と送信ボタンになります。PCの `Enter`、ログのクリック／タップ、ヘッダーの発言ボタン、またはスマホの `CHAT` ボタンで入力を開始できます。ログのスクロールや文字列選択では入力を開始しません。入力中は枠がシアンに変わり、拡大中のログはその大きさを維持します。空欄でもう一度 `Enter` を押すとゲーム操作へ戻れます。

自分の発言は端末の `localStorage` に最大40件保存し、リロードやブラウザを開き直した後も復元します。再接続時は各クライアントへ履歴を要求しますが、応答側が渡すのは自身の保存履歴だけです。受信側は実際の通信相手を著者として固定し、他人の履歴を代理配布しません。全員分を統合した画面上のログは最大100件です。各発言の情報欄には、当日分は時刻、過去分は日付と時刻を表示します。

チャットログは端末の向きにかかわらず左右余白を残して広く表示し、スマホでは半透過コントローラの背後まで利用します。コントローラの外側はログのスクロールや入力開始を受け付けます。スマホの通常時は最新の発言が読める低いログ表示に抑え、入力フォーカスがある間だけ表示面積が自動的に広がります。

端末のスリープ解除、ページキャッシュからの復帰、オフラインからの復帰を検出すると、ロビー・ゲーム・全体チャットのP2P接続を作り直します。操作位置やスコアは維持しつつ、古い相手情報を破棄して再発見します。

ただし一度も接続していない間は作り直しません。Trystero はリレーの購読を参照カウントなしにトピック名で管理するため、最初の購読が完了する前に退室と参加が重なると「購読→購読→購読解除」の順で解決し、後から届いた購読解除が新しいルームの購読を消してしまいます。この状態のタブは告知を送り続けながら何も受信しません。誰かと接続できた後は購読が確定しているため、同じ操作を安全に行えます。

孤立状態を監視して再接続する仕組みは持ちません。Trystero 自身が約5.3秒ごとに再告知し、切断されたソケットを指数バックオフで再接続し、オンライン復帰も監視しているためです。加えて退室してもリレーのソケットは閉じられず再利用されるため、ルームを作り直してもリレー層の問題は解消しません。

位置情報の送信は描画フレームではなくタイマーで駆動します。ブラウザは非表示タブの描画フレームを停止するため、以前はタブを裏に回すと送信が止まり、他プレイヤーの画面から姿が消えていました。画面ロックやタブを閉じた際は `pagehide` で退室を通知し、消えるまでの待ち時間をなくします。

他プレイヤーの表示位置は、受信した座標と速度から短時間先を予測し、現在の描画位置から補間します。通信間隔の隙間を滑らかにしつつ、復帰や場外リスポーンなど大きな座標変化は即座に反映します。

プレイヤーがロビーやゲームへ現れると、キャラクター位置へ光の輪と粒子が収束し、短い上昇音が鳴ります。退出または通信途絶でキャラクターが消えるときは、最後に確認できた位置から輪と粒子が拡散し、下降音で知らせます。効果音はロビーとゲーム画面の `SOUND` ボタンで共通して切り替えられます。

## BLAST GRID

外周の壁と格子状の柱、そして壊せるブロックで構成されたマス目のアリーナです。開始も終了も勝敗もなく、いつでも出入りできます。倒れても数秒で復帰します。

移動はロビーと同じ連続移動で、マス単位のステップ移動ではありません。通路へ入るときは中心線へ寄せる補正が入るため、角に引っかかりません。爆弾は自分がいるマスに置かれます。

**通信するのは「いつ・どのマスに爆弾を置いたか」だけです。** 爆発の時刻、連鎖、壊れたブロック、その再生は、全クライアントが同じ手順で再現します。フィールドの配置も固定シードから生成するため同期は不要です。この方式が成立するには全員の時計が揃っている必要があるため、観測した時計ずれの中央値へ各自を寄せます。導火線はフレーム時間ではなく固定タイムステップで進みます。

壊れたブロックは一定時間で再生します。外周を回る通路と中央の縦通路は常にブロックが置かれないため、迷路が塞がって動けなくなることはありません。

敵キャラは中央管理を持ちません。各クライアントが `<ピアID>:npc:<番号>` という名前の敵を数体ずつ受け持ち、担当者だけがその敵のAI・被弾・撃破・再出現を決めて結果を配信します。受信側は補間して表示します。担当者が退出すると、その配下の敵だけが消えます。

被弾は自己申告制です（競技向けのチート耐性は持ちません）。

## 仕組み

```text
静的Webサイト
    └─ 公開Nostrリレー: 部屋にいるブラウザ同士の発見とWebRTCシグナリング
          └─ WebRTC DataChannel: 位置・得点・ゲームイベントをP2Pで直接送受信
```

ワールドは配信元のホスト名で分かれます。ルームは Trystero の appId だけで識別されるため、これがないと開発サーバーから開いたページが公開サイトとまったく同じ部屋に入ります。ページ配信元のサーバーを止めても、読み込み済みのタブは公開リレー経由で通信を続けるため、閉じ忘れたタブが実プレイヤーとして居残ります。

`localhost`・ループバック・LANのプライベートアドレス・`.local` はすべて同一の「ローカル」ワールドにまとめます。開発サーバーへスマホをLAN経由で繋いで一緒に検証できるようにするためで、ポート番号は区別しません。公開サイトや将来のステージング環境は、それぞれのホスト名で自動的に別ワールドになります。

通信には Trystero の Nostr 戦略を利用しています。ゲームデータを中継する専用サーバーはありません。NATの組み合わせによって直接接続できない利用者がいる点は、STUNのみのP2P構成上の制約です。本格運用時はTURNを追加してください。

P2Pで受信するデータは反映前に検証し、**1つでも不正な項目があればメッセージ全体を破棄します**。妥当な値へ補正して受理すると、範囲外の座標を送った相手が「画面端にいる正当なプレイヤー」として描かれてしまうためです。プレイヤー状態は座標・速度の有限性と範囲、名前の長さ、色の書式を確認します。チャットは本文・名前・IDの長さを検査し、タイムスタンプは受信時刻を基準とした範囲に収めます。履歴の配列は長さ超過なら走査せず拒否します。

発言の所有権は送信元に固定します。チャットの表示名はペイロード内の自称値ではなく、そのピアのプレゼンスから解決するため、他人名義の発言を配ることはできません。パルスの所有者も受信したピアIDで上書きするため、他人の攻撃として偽装できません。ロビーの反発は宛先が自分のものだけを受け付けます。

プレイヤー状態には単調増加する連番を付けます。遅れて届いた古い位置は破棄するため、リモート機が微妙に巻き戻る現象が起きません。連番のない旧クライアントからの受信は従来どおり受理します。

プレゼンスにはプロトコル版数を載せます。自分より新しい版数のピアを見つけたら再読み込みを促すバナーを出しますが、接続とプレイは継続します。互換性が壊れる変更を入れる際に版数を上げます。

## 開発

```bash
npm install
npm run dev
npm run typecheck
npm run lint
npm test
```

`npm test` は lint・型検査・静的ビルドに加え、ロビー物理・チャット・受信データ検証の純関数ユニットテストを実行します。`main` 以外へのpushとPull Requestでは `.github/workflows/ci.yml` が同じ `npm test` を実行し、`main` へのpushでは成功した成果物だけをGitHub Pagesへデプロイします。

時刻や乱数を関数内部で取得せず引数で受け取る方針を採っています。フェイクタイマーなしで境界値を直接テストできるため、時間依存のロジックもユニットテストの対象にできます。

`http://localhost:3000` を複数タブまたは複数端末で開き、同じゲームに参加すると接続できます。公開Nostrリレーを利用するためインターネット接続が必要です。

React の `StrictMode` は使用していません。開発時のみ実行される二重マウントが、各 effect を「参加→退室→参加」の順で走らせるため、Trystero のルームがピア告知を完了できず、開発サーバー上の複数タブが互いを見つけられなくなるためです。復活させる場合は、ルームIDと再接続世代をキーにした共有レジストリを用意し、退室を遅延させて同一キーの再マウントが既存ルームを引き継ぐようにする必要があります。

## 公開

GitHub の `ainyan03/multiplay` リポジトリへ `main` ブランチを送ると、GitHub Actions がテストと静的ビルドを実行し、GitHub Pagesへ自動公開します。

公開URL: `https://ainyan03.github.io/multiplay/`

初回のみGitHubリポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定してください。Giteaの `ainyan/multiplay` は開発元、GitHubは公開用ミラーとして利用できます。

## ゲーム追加の方針

ゲーム情報と固有ルールは `app/games.ts` の `GameDefinition`（基本情報・更新・描画・アクション設定）へ分離し、`app/arcade.tsx` の共通ルーム接続・プレイヤー同期・入力・画面を再利用します。新しいゲームは定義を追加するだけでロビーの入口、人数表示、ゲーム画面へ反映できます。

自由移動と自己申告スコアだけで足りるゲームは `update` と `draw` を書きます。全員が同じ世界を共有する必要があるゲームは `kind: "arena"` を指定し、独自のシミュレーション（壁との当たり判定・共有時計・固定タイムステップ）を持ちます。共有時計は `app/clock.ts`、シード付き乱数は `app/rng.ts`、固定タイムステップは `app/timestep.ts` にあり、どのゲームからも使えます。

`?game=<id>` を付けて開くと、そのゲームへ直接入れます。

ファミコン期のゲームからは「1画面で状況が読める」「操作が方向キーと1ボタンで完結する」「短時間で勝敗がつく」という設計原則だけを参照し、固有名称・キャラクター・グラフィック・ステージは使用しません。
